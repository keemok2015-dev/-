# Project Guide

## Product and Architecture

Kora Live (كورة لايف) is an Arabic RTL football dashboard built with React 19, TypeScript, TanStack Start and Router, Vite, Tailwind CSS 4, and Lucide React. The site is deployed using Netlify's TanStack Start plugin. The index route is the product, not the original analytics dashboard template.

## Key Files

- `src/routes/index.tsx` contains the server-function-backed loader, SportsUI component, visible-page polling, manual refresh, time-zone choice, filters, search, session-only preferences, and native HTML dialogs.
- `src/components/MatchCard.tsx` renders a match with crests and Arabic kickoff times/dates; `src/components/TeamBadge.tsx` handles Netlify Image CDN, direct-image retry, and an accessible shield fallback.
- `src/lib/matches.ts` defines shared types, league configuration, Arabic digit/date/time formatting, and a rolling current-match predicate.
- `src/server/matches.functions.ts` validates the time zone and exposes the RPC wrapper. `src/server/matches.server.ts` fetches ESPN soccer scoreboards, normalizes provider fields, translates known team names, removes stale/completed events, and deduplicates and sorts current/upcoming matches.
- `src/routes/__root.tsx` defines the Arabic RTL document, siteName/siteDescription, metadata, font stylesheet, and favicon.
- `src/styles.css` defines the dark navy/emerald theme, desktop three-column dashboard, mobile single-column cards and bottom navigation, modal styling, and reduced-motion support.
- `src/router.tsx` initializes TanStack Router; `src/routeTree.gen.ts` is generated by the framework and must not be hand-edited.
- `public/favicon.svg` is the product icon. Pitch artwork and missing-logo fallbacks are code-native; team crests come from the provider and are restricted to ESPN's image host.
- `vite.config.ts` and `netlify.toml` configure Netlify deployment.

## Coding Conventions

Use typed React functional components and hooks, PascalCase component names, and descriptive camelCase variables. Follow existing single-quoted TypeScript without semicolons. Keep user-facing text Arabic and use logical CSS properties for RTL layout. Format all dates/times with shared helpers, explicit time zones, Gregorian dates, Arabic digits, and Arabic morning/evening indicators. Each score must stay visually associated with its team. Use Lucide icons with accessible labels on icon-only buttons. Preserve keyboard focus indicators, native dialog focus management/Escape support, and reduced-motion preferences.

## Intentional Limitations

Scores, match status, kickoff times, and team crests come from the public ESPN scoreboard source, not the old demonstration fixtures. Poll every 60 seconds only while visible and refresh on focus/visibility changes. Show update time and explicit source-error/empty states; never use fabricated fixtures as fallback. Data may lag and source availability is not guaranteed. Only live and upcoming matches are included; filter completed, cancelled, postponed, suspended, and stale events both server-side and client-side. Queries use single-day date keys and the provider calendar (date-range queries are not used), bounded timeouts, and a 30-day upcoming window. Saudi time is the default; the browser's time zone is an explicit alternative. Do not invent match times, club logos, broadcasts, rights, or viewing links. Channel information is region-dependent.

Subscription, favorites, and notification settings are preview state only, reset on page reload, and never imply payment, a real user account, or actual push notifications. The match server function reads an external source but persists no records. For future persistent records, use Netlify Database with Drizzle and `db/schema.ts` after reading the relevant database skills. Do not store persistent user data in browser storage, local JSON, or external database services.

## Workflow

Install using `pnpm install`. For user-run local development, use `netlify dev --port 8889`. Do not run local build/start/test commands during agent implementation; the platform validates builds automatically. Read applicable skills in `.agents/skills` or `/opt/buildhome/.agents/skills` before extending framework or Netlify features. Keep README and `.netlify/results.md` current. Never inspect `.git`, expose secrets, or create commits.
